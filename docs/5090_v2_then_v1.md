# Enter-controlled v2 → v1 experiment with continuous cameras

Start the **dual policy servers and robot processes separately**, using terminals
1–3 in the [dual yellowstick guide](5090_dual_yellowstick.md). Leave them running.
This script manages only the experiment gateways and its continuous camera
recorder. It does not start, stop or restart a policy server or FFW process.

Finish any existing terminal 4 gateway and manual terminal 5 recorder first.
The script refuses to take over existing `cosmos-bg2-execute` or
`cosmos-bg2-cameras` containers.

## Run the sequence in terminal 4

Use an interactive terminal on **5090**:

```bash
cd ~/Documents/cosmos_inference_bg2
bash deploy/5090/run_v2_then_v1.sh
```

There are **exactly two Enter actions**: first stop v2 and advance after cleanup;
second stop v1 and finalize the continuous recording. No third confirmation is needed.

The script checks that both policies are ready, then:

1. Starts the same continuous three-camera recorder used by terminal 5, and waits
   until the head and both wrist cameras have supplied frames. A separate terminal
   5 command is not needed for this sequence.
2. Starts normal **v2 execution**, with `--pause-diagnostic` enabled.
3. When you press **Enter**, sends SIGINT directly to this gateway's application.
   This has the same application behavior as Ctrl+C in the usual terminal 4:
   pause → confirm → fresh stopped observation → one diagnostic forecast that is
   never executed → save extra videos/actions → finish normal recordings → exit.
4. Waits for v2 to exit, its container to be removed, and its pause acknowledgement,
   diagnostic, camera files and imagined-video assembly to be complete. Then
   automatically starts **v1 execution**, also with `--pause-diagnostic` enabled.
5. When you press **Enter again**, finishes v1 in the same way.
6. After v1 cleanup, stops and finalizes the continuous camera recording, saves
   the sequence manifest, and returns to the shell.

Wait for each **"V2 is running" / "V1 is running"** prompt before pressing Enter.
Repeated Enter presses during cleanup are discarded. No short Docker stop timer
is used while the gateway is saving diagnostics or rendering videos.
Detailed camera status stays in each run's `events.jsonl`; the sequence uses
`--quiet-status` so the terminal shows progress and prompts instead of raw camera JSON.

Both models stay loaded, and the robot remains in the existing paused hold after
the sequence finishes. Terminals 1–3 are left running.

The [post-pause diagnostic guide](5090_pause_diagnostic.md) explains the stopped-state
sampling and `head_extra.mp4` files. The extra mode is enabled automatically by
this sequence script; ordinary gateway commands still default to having it off.

## Saved data

Each invocation creates a new directory on 5090:

```text
~/Documents/cosmos_inference_bg2/outputs/gateway/
  sequence-yellowstick-v2-v1-<UTC timestamp>-<id>/
    sequence.json
    continuous-cameras-<UTC timestamp>-<id>/
      cameras/head.mkv
      cameras/wrist_left.mkv
      cameras/wrist.mkv
      cameras/*.timestamps.jsonl
      recording_summary.json
    execute-yellowstick-v2-step18340-<UTC timestamp>-<id>/
      cameras/
      predictions/
      imagined/head.mp4
      imagined/head_extra.mp4
      imagined/wrist_left_extra.mp4
      imagined/wrist_right_extra.mp4
      imagined/rollout_extra.mp4
      diagnostics/pause/
    execute-yellowstick-v1-step18420-<UTC timestamp>-<id>/
      ...same layout...
```

`sequence.json` links the v2, v1 and continuous-camera folders and reports whether
the sequence completed, was cancelled or failed. Raw model outputs retain the
existing v1/v2 server locations and are linked by each run's epoch/request IDs.
The plain imagined videos are the originals. Each `*_extra.mp4` is a separate
version containing that original followed by the never-executed diagnostic forecast.

## Cancellation and incomplete cleanup

**Ctrl+C in this sequence terminal cancels the remaining sequence.** The current
gateway is asked to pause and finish saving, then the continuous recorder is
finalized. It will not automatically start the next policy. A second Ctrl+C also
asks the current gateway to cancel/defer the diagnostic or recording export.

If v2 exits unexpectedly, its diagnostic fails, normal recordings remain pending,
or the continuous recorder stops, the script does **not** proceed to v1. It
finalizes the processes it started and reports the failure and saved folder.
Only containers bearing this sequence's ownership label can receive its signals;
the policy servers and robot containers are never signalled.
An interrupted request with no received prediction is excluded from video assembly
only when it is proven not submitted, explicitly refused as busy, or still has no
saved artifact after the later diagnostic completed on the same server. Such requests
are retained in metadata as cancelled; a missing received prediction still fails cleanup.

You can allow more time for artifact collection, for example:

```bash
cd ~/Documents/cosmos_inference_bg2
bash deploy/5090/run_v2_then_v1.sh --recording-wait 120
```

To inspect all three commands without starting or contacting anything:

```bash
cd ~/Documents/cosmos_inference_bg2
bash deploy/5090/run_v2_then_v1.sh --dry-run
```

The workflow is tested with fake processes, control/inference endpoints and
recording receipts. Live sequence execution is left to the operator.
